#### FINDINGS
Warning RB-014 The ports lan3 are removed from the switch 'lan' so they can be used on their own: this is the first command of the script, so do not connect your PC to those ports while running it.
Warning RB-021 The changes to the management interface 'lan' are in the part 'management', near the end: if your PC is connected to 'lan', the connection drops after that part. Give your PC a static address in the new subnet of 'lan' (its DHCP server comes only with the last part), reconnect to the new address and run the remaining parts (the last one is the DHCP server of 'lan').
Warning RB-023 IPsec tunnels: proposals, DH groups and IKE version are written explicitly with the old defaults. Dead peer detection: the 5.2 default (enable) becomes the 8.0 default (on-demand). Check them with the administrator of the other side.
Warning RB-039 SSL VPN converted to IPsec dial-up 'dialup_vpn' (IKEv2, EAP, group 'VPN-Utenti', clients 10.212.134.200-10.212.134.210). TO REVIEW before production.
Warning RB-040 FortiClient: create an IPsec VPN connection to 'dialup_vpn' (remote gateway = WAN address, pre-shared key from the password summary, IKE version 2, EAP with username and password). Users authenticated by LDAP need EAP-TTLS, supported by FortiClient and EMS 7.4.3 and later (SSL VPN to IPsec VPN migration guide, LDAP-based user authentication). FortiClient 7.4.4 and later do not support IKEv1.
Warning RB-069 Policy 1: the custom profiles webfilter-profile Ufficio-Web do not exist on the target and are replaced by the preloaded FortiOS 8.0 profiles webfilter-profile default, so the policy keeps a protection of the same kind. Recreate the custom profiles if you need their exact settings.
Warning RB-052 Policy 6 sends traffic out of 'lan3', which takes no default route from DHCP/PPPoE (defaultgw disable, as on 5.2) and has no static route: FortiOS chooses the outgoing interface from the routing table, so the policy may never match. Add a route or a policy route through 'lan3' if needed (the source had the same behaviour).
Warning RB-076 LDAP users of the SSL VPN (anna.bianchi, server AD-Ufficio) cannot log in to the IPsec dial-up as it is: with IKEv2 FortiClient must use EAP-TTLS against an LDAPS server, which needs the CA certificate of the AD server imported, 'set secure ldaps' and 'set ca-cert' on the LDAP server, FortiClient 7.4.3 or later and the configuration synchronised from FortiClient EMS (Administration Guide 8.0.2, Add LDAP user authentication). LDAP servers without LDAPS: AD-Ufficio. Configure it by hand before giving the VPN to these users.
Warning RB-077 The SSL VPN portal full-access had web mode enabled: web mode (now Agentless VPN) is not available on FG-40F with FortiOS 8.0 (Release Notes 8.0.2) and is not migrated. Users who connected from a browser need FortiClient.
Warning RB-072 IPsec tunnel 'to-sede2' uses settings that Fortinet does not recommend (IKEv1; phase1 DH 14 5; phase1 3des-sha256 aes128-sha1 aes256-sha1 3des-sha1; phase2 to-sede2-p2 DH 14 5; phase2 to-sede2-p2 aes128-sha1 aes256-sha1 3des-sha1 3des-sha256): kept for compatibility with the other site, to be updated together with it (IKEv2, DH groups 19-21, AES-GCM or AES with SHA-256). Sources: FortiOS 8.0 Administration Guide, Phase 1 and Phase 2 configuration (DES, 3DES, MD5 and SHA1 not recommended; DH groups 1, 2, 5, 14, 22-27 insecure for Security Rating Insights); FortiOS 8.0 Best Practices, IPsec VPN remote access (prefer IKEv2).
Info RB-029 The script is meant for a FortiGate with its factory configuration and the firmware of the target version.
Warning RB-031 FG-40F is a 2 GB RAM model: no SSL VPN web mode, no proxy-based features (Release Notes 8.0.2, Special notices).
Warning RB-032 4 passwords and keys are new: see the password summary, change them at first login and give the new VPN keys to the other side.
